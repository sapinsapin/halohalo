# Running the speech server on the GB10, and reaching it through NYO

The GB10 (Dell Pro Max with GB10, the DGX Spark class: 128 GB of unified
memory, a Blackwell GPU, arm64) is where the published models are meant to
run. This page is the operator's path: what to run on the machine, how NYO
gets to it, and what to measure. It follows NVIDIA's DGX Spark playbooks
where they apply (the NGC PyTorch container as the base image, Tailscale for
private access) and NYO's own compute-node flow for public access.

## 1. Which models

| Task | Model | Why |
|---|---|---|
| TTS | `sapinsapin/orpheus-3b-0.1-pretrained-char-pld-<lang>` on `unsloth/orpheus-3b-0.1-pretrained` + `hubertsiuzdak/snac_24khz` | The best published TTS per language: round-trip CER 4-12 % against SpeechT5's 30-300 % (`dashboard/tts_compare.json`). Nine languages; no Pangasinan adapter yet. |
| ASR | `sapinsapin/whisper-large-v3-pld-<lang>-norm` | The most accurate per language on the honest speaker- and prompt-disjoint split (`halolib.finetune._BEST_ASR`); English falls back to `whisper-small-pld-eng`. |
| TTS fallback | `sapinsapin/speecht5_tts-pld-<lang>` (`TTS_ENGINE=speecht5`) | What tts-ws serves: all ten languages, realtime even on CPU, much worse audio. The repos are private; set `HF_TOKEN`. |

Memory, roughly: Orpheus base 6.6 GB in bf16 + SNAC + one adapter per
language (tens of MB each); whisper-large-v3 about 3 GB in fp16 per language
(`ASR_MAX_RESIDENT`, default 3, bounds how many stay loaded). Twenty gigabytes
serve three languages of both with room to spare; the whole fleet of nine
fits beside a 27B chat model on a 128 GB machine.

## 2. Path A: through NYO (the compute-node flow)

The machine joins NYO as a compute node and NYO deploys the speech server
into it; the gateway brokers access and nothing on the GB10 listens on the
internet. This is the `byoc` flow in `aineolab/llm-gateway-hub`
(`docs/byoc-cluster.md` there), with a `speech` runtime.

```bash
# on the GB10, once (from /byoc on the gateway: the one command with your token)
curl -fsSL https://llm.nyolab.ai/byoc/bootstrap.sh | bash -s -- --gateway https://llm.nyolab.ai --token nyo_enroll_…

# the speech runtime image is built on the node from this directory (10-20 min, once)
nyo-node build-runtime speech

# deploy; the catalog entry is sapin-speech (TTS fil,ceb,hil + ASR fil,ceb,hil by default)
nyo-deploy sapin-speech
nyo-node logs sapin-speech          # weights download on first start
```

Or press **Deploy** on `/byoc`, or ask the NYO Compute connector to
`deploy_model sapin-speech`. When it is ready the model is callable with your
NYO keys:

```bash
# speech, streamed PCM S16LE 16 kHz
curl -N https://llm.nyolab.ai/api/public/v1/audio/speech -H "Authorization: Bearer $NYO_API_KEY" \
  -H 'content-type: application/json' -d '{"model":"sapin-speech","input":"Maayong buntag sa tanan.","language":"ceb"}' > out.pcm
ffplay -f s16le -ar 16000 -ac 1 -i out.pcm

# recognition
curl https://llm.nyolab.ai/api/public/v1/audio/transcriptions -H "Authorization: Bearer $NYO_API_KEY" \
  -F model=sapin-speech -F language=ceb -F file=@clip.wav

# a socket session for the Agora contract: NYO mints a ticket, you connect to the machine
curl -X POST https://llm.nyolab.ai/api/public/v1/audio/session -H "Authorization: Bearer $NYO_API_KEY" \
  -H 'content-type: application/json' -d '{"model":"sapin-speech"}'
# -> {"tts_url":"wss://<node>/m/sapin-speech/tts?ticket=…","asr_url":"wss://<node>/m/sapin-speech/asr?ticket=…","expires_at":…}
python tools/ws_client.py 'wss://<node>/m/sapin-speech/tts?ticket=…' "Maayong buntag." --lang ceb
```

The playground at `https://llm.nyolab.ai/playground` (Speak and Transcribe
tabs) does exactly this in a browser.

`nyo-deploy` has no flag for the server's environment yet, so to change the
languages or the engine, edit the `sapin-speech` recipe in the gateway's
`src/lib/byoc.ts` (its `env`), or run path B.

## 3. Path B: by hand, with your own tunnel

For a test that does not go through NYO's control plane.

```bash
cd halohalo/serving/speech-ws
docker build -t sapin/speech-ws .           # arm64: nvcr.io/nvidia/pytorch:25.09-py3 base
docker run -d --name speech --gpus all --restart unless-stopped -p 127.0.0.1:8000:8000 \
  -v /var/lib/nyo/models:/models -e HF_TOKEN=$HF_TOKEN -e NYO_SERVING_KEY=$(openssl rand -hex 24) \
  -e TTS_LANGS=fil,ceb,hil -e ASR_LANGS=fil,ceb,hil sapin/speech-ws
curl -s localhost:8000/healthz                # ready:true once the weights are down and warm
```

Then one of:

- **Private (DGX Spark playbook, Tailscale).** Install Tailscale on the GB10
  and on the client; point the client at `ws://<tailscale-ip>:8000/tts`.
  Nothing public, no TLS needed on a tailnet. For a laptop on the same LAN,
  `ssh -L 8000:127.0.0.1:8000 iotim@dwnd-01.local` does the same (what the
  first GB10 demo used).
- **Public, quick.** `cloudflared tunnel --url http://127.0.0.1:8000` prints a
  random `https://….trycloudflare.com`; `wss://…/tts` works through it. The
  URL changes on every restart; good for a day's test.
- **Public, for keeps.** A named Cloudflare tunnel on your own hostname, or
  the plain `ws://<ip>:8765` host the Azure demo used (no TLS stack needed
  on the device, cleartext on the internet).

Add it to NYO as a backend by hand (Admin → Backends: provider `speech`,
base URL `https://<host>/v1`, credential = the serving key) with a route
named `sapin-speech`; the gateway then treats it exactly like a deployed
node's model.

## 4. Measuring

```bash
python tools/ws_client.py ws://127.0.0.1:8000/tts "Maayong buntag sa tanan. Salamat sa inyong pagpaminaw." --lang ceb --expect-streaming
python tools/ws_protocol_test.py ws://127.0.0.1:8000/tts
python tools/asr_client.py ws://127.0.0.1:8000/asr clip.wav --lang ceb
```

`ws_client.py` prints time to first audio and the realtime factor and checks
alignment, byte order, clipping and speech rate. Record them in the table
below the first time the server runs on the GB10; nothing here has been
measured there yet.

| Engine | Backend | TTFA | RTF | Notes |
|---|---|---|---|---|
| orpheus | transformers | | | |
| orpheus | llamacpp | | | |
| speecht5 | GPU | 0.12-0.16 s | 0.09-0.10 | measured 2026-09-30 on the GB10 (tts-ws, fp16) |
| whisper-large-v3 | transformers fp16 | | | |

What to expect: HF `generate` on a 3B model runs at roughly 25-35 tokens/s
on a GB10 (memory-bound, 273 GB/s), against the 82 tokens/s that realtime
speech needs, so Orpheus through transformers is about a third of realtime
and the device should buffer a sentence before playing, as the TTS contract
already says. Time to first audio is the first 28 tokens, about a second.

## 5. Faster Orpheus: llama.cpp

A GGUF of the base model with the adapters as LoRA GGUFs runs two to three
times faster on this hardware and keeps one process for all languages, with
the adapter chosen per request. Not yet run on the GB10; the recipe:

```bash
# convert once (the llama.cpp checkout from scripts/custom-models/gemma4-gb10.sh)
python convert_hf_to_gguf.py unsloth/orpheus-3b-0.1-pretrained --outtype q8_0 --outfile orpheus-q8.gguf
for l in fil ceb hil; do
  python convert_lora_to_gguf.py --base unsloth/orpheus-3b-0.1-pretrained \
    sapinsapin/orpheus-3b-0.1-pretrained-char-pld-$l --outfile lora-$l.gguf
done
llama-server -m orpheus-q8.gguf --lora lora-fil.gguf --lora lora-ceb.gguf --lora lora-hil.gguf \
  --lora-init-without-apply --port 8081 -ngl 99 -c 4096 --api-key "$NYO_SERVING_KEY"
# then
ORPHEUS_BACKEND=llamacpp LLAMACPP_URL=http://127.0.0.1:8081 LLAMACPP_LORA=fil=0,ceb=1,hil=2 python serve.py
```

The server sends the prompt as token ids (the frontend is identical) and
parses the `<custom_token_N>` stream; SNAC decoding is the same code.
